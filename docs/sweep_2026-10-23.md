# Batch run of all static-EASY versions (2026-10-23)

Question from the team: of the expert versions, how many run on Babel, and why do the others fail? Is the earlier
"7 runnable cases" a full screen? (It was not: before this run only 33 versions had ever been executed.)

## What was run

401 versions, each run unmodified (path rewrites and the 3 logged API-rename patches only) and graded with MLE-bench:

| stage | what | versions | notebooks |
|---|---|---:|---:|
| A | other versions of the 7 notebooks that already had an OK version (tests "if one version runs, others do too") | 113 | 7 |
| B | every static-EASY version not run before, aes2 + gquest | 158 | 17 |
| B | every static-EASY version, hms (prepared today) | 130 | 10 |

Stage A skips 38 versions that took > 15 min on Kaggle (all aes2, mostly training). With the 31 EASY versions run
earlier, this covers 405 of the 406 static-EASY versions in the 4 gradable competitions (the one left is ranzcr,
whose 13 GB data is not prepared). Static labels come from `triage_static.py` re-run on the cached Kaggle lookups.

Setup: SLURM arrays on `preempt` (CPU and 1-GPU jobs, 4 CPU, 24 GB, 20 min per version; GPU unused), shards via
`slurm/sweep.sbatch`, list from `src/make_sweep.py`. Then two reruns of failures with fixable causes:

- missing package or out of memory (47 versions): after adding packages to `kaggle-run` and with 64 GB;
- pandas 3 `Invalid value ... for dtype` errors (56 hms versions from 2 notebooks, written in early 2024): in a venv
  on top of `kaggle-run` with pandas 2.3.3 and scikit-learn 1.5.2 (`/data/user_data/pengchej/software/venvs/
  kaggle-run-pandas2`, kernel `kaggle-run-pandas2`). Rows record the env in `run_env`.

## Results

Each version counts once, by its latest run (`python src/sweep_report.py --tag sweep-1023`).

| | aes2 | gquest | hms | total |
|---|---:|---:|---:|---:|
| versions run | 211 | 60 | 130 | 401 |
| **run and graded** | 79 | 26 | 66 | **171** |

**Runnable cases** (v_k and v_k+1 both OK, `triage/runnable_cases.csv`): **145**, up from 7, from 18 notebooks
(aes2 59, hms 56, gquest 30). **None is in the 70 notebooks selected for knowledge extraction.** Where both versions
have a Kaggle score, the improvement direction matches Kaggle in 47 of 67 cases.

**Why the other 230 fail:**

| reason | versions |
|---|---:|
| error in the expert's code (undefined name, syntax error, …) | 91 |
| runs but never writes submission.csv (mostly EDA notebooks) | 63 |
| missing package (keras/TensorFlow, h2o, google.generativeai, …) | 18 |
| external Kaggle input missing | 17 |
| old code vs new library versions | 17 |
| out of memory (64 GB) | 4 |
| timeout (20 min) | 10 |
| file or path not found (author's local paths, files never created) | 7 |
| needs GPU | 2 |
| invalid submission | 1 |

206 of the 230 failed versions (90%) have no Kaggle score either, so the expert most likely never got them running.

**"If one version runs, others do too?"** Partly. For the 7 notebooks that already had an OK version, 44 of 113
other versions run (39%); per notebook from 0% to 74%.

Categories come from the final error line (`sweep_report.py`, first matching rule), so they are approximate.
