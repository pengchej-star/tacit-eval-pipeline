# 小实验：不告诉 LLM 专家选了什么，重新推断 visit record（2026-11-06）

**问题**：Yaqing 流水线第 5 步写 visit record 时，prompt 里写明了"专家选了哪个选项"，还附上回看整段写成的 item。证据会不会跟着答案走？

**做法**（`blind_visits.py`，结果在 `blind_visits.json`）：
- 对 RANZCR 完整运行里的两个节点，重新推断全部 27 次访问："归一化参数策略"9 次、"推理分辨率策略"18 次。
- 检查列表、yes/no/not_checked 的规则、模型（`wine-claude-opus-4-6`，温度 0）都和她一样。
- 给 LLM 的只有改动之前就能看到的东西：任务描述、这位专家之前的改动和分数、改动前那个版本的原始代码、节点的选项，以及他以前在这里选过什么。
- **不给**：这一步选了什么、这一步的改动摘要、episode item。
- 然后用她现成的重要度（`6_scores.json`）和她的排名公式，看两版记录各自能不能"预测"专家的选择。
- 花费约 $2–3。

## 结果

| | 归一化节点（9 次，3 个选项） | 分辨率节点（18 次，5 个选项） |
|---|---|---|
| 原始记录 vs 不给答案的记录，标注一致的比例 | 75% | **55%** |
| 用她的打分预测专家选择：原始记录 | 9/9（100%） | 12/18（67%） |
| 用她的打分预测专家选择：不给答案 | 7/9（78%） | **9/18（50%）** |
| 对照：随便猜 / 永远猜最常见的选项 | 33% / 56% | 20% / **61%** |

**归一化节点上的翻转消失了**（y = yes，n = no，· = 没查）：

| 步 | 专家选了 | E133 标准值可查（原始 → 不给答案） | E367 最好分来自标准值（原始 → 不给答案） |
|---|---|:-:|:-:|
| v15→16 | 继续试 | n → **y** | y → y |
| v17→18 | 继续试 | n → **y** | n → **y** |
| v18→19 | 继续试 | n → **y** | n → **y** |
| v20→21 | 继续试 | n → **y** | n → **y** |
| v21→22 | 改回标准值 | y → y | y → y |

不给答案时，这两条事实从头到尾都是 yes。这本来就是事实，因为 ImageNet 标准值一直有据可查，v13 用标准值的分数也一直是最好的。原始记录里的 no，是 LLM 在知道"专家选了继续试"之后写出来的。

**没预测中的 2 步**（v15→16、v18→19）：不给答案的证据指向"改回标准值"，而专家当时选的是继续试。也就是说，证据指向的是专家 5 个版本之后才做的、也是我们 pivot 实验里 agent 在 v17 就做了的那个选择。

## 怎么读

1. **证据确实会跟着答案走**：知道答案和不知道答案，分辨率节点上将近一半的标注不一样。
2. **原来的高命中率有一部分来自泄漏**。不给答案后，分辨率节点的命中率从 67% 掉到 50%，**低于"永远猜最常见的选项"（61%）**。
3. **"预测专家选什么"本身可能不是好目标**。专家也会做错的选择，比如归一化那 5 步。小抄如果学会了预测专家的错误，就是在教 agent 犯同样的错。也许应该改成预测"哪个选择让分数变好"。这一点值得和 Sherry 讨论。

## 局限

- 只有 2 个节点、27 次访问，每次只跑了一遍，只能当信号看。
- 重要度是她用原始（知道答案的）记录猜出来的，对不给答案的记录不利。公平的做法是用不给答案的记录重新打分，并在没参与打分的专家上检验。
- 不给答案的版本看了改动前的原始代码。原始运行很可能也看了代码，但看的是改动本身的 diff，两者给的信息不完全一样。

## 扩大版：4 个上层节点、479 条（同一天稍晚）

同样的做法，用在 RANZCR 访问最多的 4 个上层节点上：根"把分数提上去"、评估与验证、推理与后处理、集成。结果在 `blind_visits_top.json`，评估脚本是 `blind_eval.py`。这一轮约 $20.5。

这次补上了 Sherry 第 6 步要求、Yaqing 新代码删掉的检验：**每次留出一位专家，用其他专家的记录去预测他的选择**。比较三种预测方法：
- **统计法**：看每条检查是 yes / no / 没查时，其他专家分别选了什么（朴素贝叶斯）；
- **Yaqing 的打分**：LLM 猜的重要度，不重新拟合；
- **对照**：永远猜其他专家最常选的那个选项。

| 节点 | 访问 / 专家 / 选项 | 两版标注一致 | 永远猜最常见 | 统计法：原始 → 不给答案 | Yaqing 的打分：原始 → 不给答案 |
|---|---|---|---|---|---|
| 根"把分数提上去" | 278 / 10 / 9 | 66% | 13% | 29% → **25%** | 18% → 14% |
| 评估与验证 | 52 / 9 / 7 | 57% | 79% | 85% → 77% | 65% → 63% |
| 推理与后处理 | 51 / 8 / 7 | 69% | 35% | 31% → 18% | 39% → 31% |
| 集成 | 98 / 7 / 5 | 70% | 79% | 68% → 53% | 11% → 26% |
| **合计 479 条** | | | **36%** | **44% → 36%** | **24% → 24%** |

**怎么读**：
1. **不告诉答案，30–43% 的标注会变**，说明原始记录很大程度上跟着答案走。
2. **用不给答案的记录，统计法的总命中率（36%）和"永远猜最常见选项"一样**。原始记录上多出来的 8 个百分点（44%），来自答案泄漏。
3. **只有根节点还留着一点信号**：不给答案的记录预测对 25%，高于"猜最常见"的 13% 和随便猜的 11%。也就是说，"往哪个大方向改"可能从可见证据里推得出来，往下层就推不出来了。
4. **Yaqing 用 LLM 猜的重要度，比"猜最常见选项"还差**（24% 对 36%），不管用哪版记录都一样。

**结论**：只靠 TraceML 能看到的东西（之前的改动和分数，加上改动前的代码），目前推不出能预测专家选择的"注意力"。唯一的例外是最上层，那里有微弱的信号。

**局限**：只有 RANZCR 一个比赛、10 位专家，每条只跑了一次；统计法用的是最简单的朴素贝叶斯；"专家选了什么"本身也有噪声，专家会做错选择（见上文归一化节点）。

## 两个补充检查（组会前）

**A. 差异是不是 LLM 的随机波动？** 从 479 条里随机抽 50 个（步，节点），在"不给答案"的设置下再跑一遍（`blind_rerun.json`，约 $3）：

| | 检查状态一致 | yes 和 no 互相翻转 |
|---|---:|---:|
| 不给答案 vs 不给答案再跑一遍 | 94% | 1% |
| 原始 vs 不给答案（同样的记录） | 68% | 13% |

LLM 自己和自己基本一致，所以原始记录和不给答案的记录之间的差异，来自"给不给答案"，而不是随机波动。

**B. 证据能不能预测"这一步会不会提分"？** 预测目标从"专家选了哪个"换成"这一步分数涨没涨"。只用有分数的 335 条，同样每次留出一位专家：

| | 命中率 |
|---|---:|
| 永远猜最常见 | 50% |
| 原始记录 | 58% |
| 不给答案的记录 | 56% |

不给答案的证据对"会不会提分"有弱信号（+6 个百分点，约两个标准误），对"专家选哪个"则没有信号（36% 对 36%）。这支持"小抄应该学'什么情况下做什么会提分'，而不是'专家会怎么选'"这个方向，但信号很弱，需要在更多比赛上验证。

## 给 Yaqing：这里的代码是什么、怎么跑

**没有改动你的 `new_extraction` 代码。** 这里是两个独立的小脚本，只读取你 11 月 4 日 RANZCR 完整运行的结果。

- **`blind_visits.py`**：第 5 步（visit record）的"遮住答案"版本。和你的 `visits.py` 相比：
  - **去掉了三样**：这一步选了哪个选项（`Taken:`）、这一步本身的目的和改动摘要、episode item 的文字（回看整段写的，含后见之明）；
  - **保留**：任务描述、这位专家之前每一步的目的、摘要和 LB 分数（只到 v_old）、节点的选项、他以前在这个节点选过什么、同一份检查单、同样的 yes/no/not_checked 规则、同一个模型（`wine-claude-opus-4-6`，温度 0）；
  - **加了一样**：v_old 那一版的原始 notebook 代码（截取前 14,000 个字符）；
  - **输出**：每个（步，节点）一条，格式和 `5_visits.json` 里的 `checks` 一样，可以直接喂给你 `scores.py` 的 `rank()`。同一步、同一节点如果有多条 item，只调用一次。
- **`blind_eval.py`**：每次留出一位专家来评估。比较三种预测：永远猜最常见的选项、统计法（对 yes/no/not_checked 做朴素贝叶斯）、你 `6_scores.json` 里 LLM 猜的权重。原始记录和遮住答案的记录各算一遍。

**怎么跑**（需要 `openai`、`pyyaml`，以及 `trajectories_human.tar.gz` 解压出来的原始 notebook）：

```bash
export LITELLM_API_KEY=...                                  # CMU 网关
export EXTRACTION_ROOT=/path/to/new_extraction
export RUN_DIR=$EXTRACTION_ROOT/archive_old_runs/_per_competition_attempt/ranzcr-clip-catheter-line-classification/episode
export HUMAN_DIR=/path/to/human                             # 下面是 <key_id>/versions/vNNN.ipynb
WORKERS=16 python blind_visits.py out.json T,T.7,T.1,T.6     # 节点 id 用逗号隔开；结果逐条缓存在 out.cache.jsonl
SUBSET=rerun_subset.json python blind_visits.py rerun.json T,T.7,T.1,T.6   # 只跑列表里的（步，节点）
python blind_eval.py out.json                                # 打印每个节点和合计的命中率
```

成本：用 Opus 4.6，每条约 $0.04；4 个上层节点的 479 条约 $20，48 个并发大约 15 分钟。
