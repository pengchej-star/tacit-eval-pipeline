# 小实验：不告诉 LLM 专家选了什么，重新推断 visit record（2026-11-06）

**问题**：Yaqing 流水线第 5 步写 visit record 时，prompt 里写明了"专家选了哪个选项"，还附上回看整段写成的 item。证据会不会跟着答案走？

**做法**（`blind_visits.py`，结果在 `blind_visits.json`）：
- 对 RANZCR 完整运行里的两个节点，重新推断全部 27 次访问："归一化参数策略"9 次、"推理分辨率策略"18 次。
- 检查列表、yes/no/not_checked 的规则、模型（`wine-claude-opus-4-6`，温度 0）都和她一样。
- 给 LLM 的只有改动之前就能看到的东西：任务描述、这位专家之前的改动和分数、改动前那个版本的原始代码、节点的选项，以及他以前在这里选过什么。
- **不给**：这一步选了什么、这一步的改动摘要、episode item。
- 然后用她现成的重要度（`6_scores.json`）和她的排名公式，看两版记录各自能不能"预测"专家的选择。
- 花费约 $2–3。

## 结果

| | 归一化节点（9 次，3 个选项） | 分辨率节点（18 次，5 个选项） |
|---|---|---|
| 原始记录 vs 不给答案的记录，标注一致的比例 | 75% | **55%** |
| 用她的打分预测专家选择：原始记录 | 9/9（100%） | 12/18（67%） |
| 用她的打分预测专家选择：不给答案 | 7/9（78%） | **9/18（50%）** |
| 对照：随便猜 / 永远猜最常见的选项 | 33% / 56% | 20% / **61%** |

**归一化节点上的翻转消失了**（y = yes，n = no，· = 没查）：

| 步 | 专家选了 | E133 标准值可查（原始 → 不给答案） | E367 最好分来自标准值（原始 → 不给答案） |
|---|---|:-:|:-:|
| v15→16 | 继续试 | n → **y** | y → y |
| v17→18 | 继续试 | n → **y** | n → **y** |
| v18→19 | 继续试 | n → **y** | n → **y** |
| v20→21 | 继续试 | n → **y** | n → **y** |
| v21→22 | 改回标准值 | y → y | y → y |

不给答案时，这两条事实从头到尾都是 yes。这本来就是事实，因为 ImageNet 标准值一直有据可查，v13 用标准值的分数也一直是最好的。原始记录里的 no，是 LLM 在知道"专家选了继续试"之后写出来的。

**没预测中的 2 步**（v15→16、v18→19）：不给答案的证据指向"改回标准值"，而专家当时选的是继续试。也就是说，证据指向的是专家 5 个版本之后才做的、也是我们 pivot 实验里 agent 在 v17 就做了的那个选择。

## 怎么读

1. **证据确实会跟着答案走**：知道答案和不知道答案，分辨率节点上将近一半的标注不一样。
2. **原来的高命中率有一部分来自泄漏**。不给答案后，分辨率节点的命中率从 67% 掉到 50%，**低于"永远猜最常见的选项"（61%）**。
3. **"预测专家选什么"本身可能不是好目标**。专家也会做错的选择，比如归一化那 5 步。小抄如果学会了预测专家的错误，就是在教 agent 犯同样的错。也许应该改成预测"哪个选择让分数变好"。这一点值得和 Sherry 讨论。

## 局限

- 只有 2 个节点、27 次访问，每次只跑了一遍，只能当信号看。
- 重要度是她用原始（知道答案的）记录猜出来的，对不给答案的记录不利。公平的做法是用不给答案的记录重新打分，并在没参与打分的专家上检验。
- 不给答案的版本看了改动前的原始代码。原始运行很可能也看了代码，但看的是改动本身的 diff，两者给的信息不完全一样。
